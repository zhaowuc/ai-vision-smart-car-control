## 打开和继续已有数据

在 `senslab/` 目录运行：

```sh
python -m http.server 8080
```

使用独立的桌面 Chrome/Edge 标签页访问 `http://localhost:8080/`。也可直接打开完整 `SensLab-Personal.html`。`src/index.html` 是可编辑的多文件源码入口。分片加载器需要 HTTPS 或 localhost 的 WebCrypto 与 DecompressionStream；不能直接用 `file://` 打开加载器并期待跨文件 fetch 正常工作。

继续使用与原来相同的地址、浏览器和配置文件，才会读到该源下的 localStorage。更换域名、端口、浏览器或由网页切换到文件地址时，先在原入口导出 JSON，在新入口导入；不同源不会自动同步。不要清理站点数据。正式实验前建议保留一份外部 JSON 备份。

已保存的有效设置优先于历史预填。1600 DPI、75.2 cm/360、暂估 20 cm 横向行程等历史值，只能填补缺失字段并等待确认，不代表自动完成物理校准。20 cm 估计只用于范围提示。窗口或 FOV 变化与 DPI、设备、输入路径变化分开处理；普通鼠标移动诊断仅证明收到了事件，不等于物理输入校准。

鼠标锁定后系统箭头会隐藏，画面中央固定准星应持续可见。微调、切换、转向需要左键单击；跟枪只需让准星覆盖目标。按 Esc、失焦或锁定丢失会暂停当前小任务，恢复需要用户点击重新锁定。若没有有效校准，可进行不计分练习，不能将其结果视为可靠的物理 cm/360 推荐。

## 默认深度实验：120分钟预算

| 阶段 | 内部安排 | 计划预算 |
| --- | --- | ---: |
| 环境核对与共同热身 | 核对及阅读120秒；四类任务各30秒教程、120秒基准热身；休息180秒 | 900秒 / 15分钟 |
| 四条件粗筛 | 4块×480秒；相邻块之间3次×60秒休息 | 2100秒 / 35分钟 |
| 阶段休息 | 保存进度、释放鼠标、放松手臂，不展示条件成绩 | 600秒 / 10分钟 |
| 三条件配对复测 | 原基准及最多2个候选，3轮×3块×300秒 | 2700秒 / 45分钟 |
| 报告和应用 | 复测完成立即出报告；阅读、导出与跨游戏换算 | 预留900秒 / 15分钟，不强制倒计时 |

完整计划为7200秒，其中测试与休息6300秒。开始前复用已有设置和有效校准，只确认硬件及输入路径未变化，不重新测量DPI或10厘米。120秒阅读与环境核对预算可以由用户提前确认，提前完成的部分从预计耗时扣除，其余正式任务和必要休息不静默缩短。教程和共同热身使用原基准，不进入推荐成绩。

每个粗筛块：180秒不计分适应（覆盖四类任务）＋四类任务各60秒＋三次10秒过渡＋30秒评分预算＝480秒。每个复测块：60秒再适应＋四类任务各45秒＋三次5秒过渡＋15秒评分预算＋30秒组后休息＝300秒。所有时间由单次协议调度，不再叠加旧3秒倒计时或每任务20秒休息。

深度实验候选按当前基准动态生成：`baseCm × 1.25、1、0.8、0.64`。75.2的示例为94、75.2、60.16、48.128 cm/360；这些是待比较的局部候选，不是预设推荐范围。原基准始终保留，越界条件说明原因，不静默截断或复制条件凑数。舒适行程估计不用于剔除候选。

粗筛仅用于选取符合冻结精度和舒适度规则的最多两个非基准候选。三条件复测采用随机标签映射后的三轮拉丁方。只有一个合适候选时，执行基准与候选的四轮AB/BA/BA/AB（或对称顺序），共8块、40分钟复测，更新为115分钟总预算（测试与休息100分钟＋报告预留15分钟）。没有可比较候选时不进行虚假复测，也不强制等待10分钟阶段休息；显示原因并允许保留原值或结束，结构计划为65分钟（前置与粗筛50分钟＋报告预留15分钟）。这些计划还会按提前确认和额外等待调整。

同轮各条件共享正式任务种子、难度、角度分布和轨迹规则；每轮使用新序列，适应序列与正式序列分开。任务数量可能随完成速度不同，不能声称每个条件实际看到的目标总数相同。顺序平衡可减少位置影响，不保证消除练习、疲劳或前一条件的残留影响。条件数值在实验结束前遮蔽，这不是真正双盲。

费力度和疼痛必须明确回答，未答时停下来等待。延长适应、主动暂停、评分超时和异常重测单独记录并增加实际耗时。180秒或60秒适应是工程预算，不代表对所有人都充分。休息可以延长，疼痛时停止正式实验，不为凑足时间继续测量。

## 保留的10/20分钟模式

| 模式 | 共同熟悉 | 粗筛 | 阶段休息 | 复测 | 计划合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 20 分钟完整 | 40 秒 | 5 条件 × 80 秒 | 40 秒 | 最多 3 条件 × 3 轮 × 80 秒 | 1200 秒 |
| 10 分钟快速 | 40 秒 | 3 条件 × 80 秒 | 40 秒 | 基准与 1 候选 × 2 轮 × 70 秒 | 600 秒 |

80 秒组由 15 秒适应、四类任务各 12 秒、三次过渡各 2 秒、评分与休息 11 秒组成。70 秒组使用 10 秒适应、相同 48 秒任务和 6 秒过渡、评分与休息 6 秒。候选数量不足时按实际数量执行。首次教程、用户暂停、延长适应、超出预算的评分等待和异常重测另计，计划时长不是强制截止时间。费力度和疼痛未作答时等待用户，不自动补成 0 分或无疼痛。

20 分钟候选为基准距离的 0.64、0.8、1、1.25、1.5625 倍；10 分钟只比较局部的 0.8、1、1.25 倍。例如 75.2 cm/360 对应 60.16、75.2、94 cm/360。数值较小意味着角增益较大，75.2 → 60.16 的相对角增益为 1.25 倍，即增加 25%。界面展示精度不代表物理测量具有同等精度。

粗筛随机排序并只用于挑选复测候选。复测保留原基准，使用平衡条件顺序、每轮新目标种子，以及同轮一致的任务难度和任务顺序。正式测量结束前遮蔽条件数值，这不是真正双盲。进入复测后冻结候选和规则。

最终分析与旧按测试日 bootstrap 的路径分开，以同日2–4轮配对复测为依据，展示原始表现、综合与各项变化、每轮方向、中位表现和观察到的最小—最大范围，以及舒适度、输入质量、样本不足和基准漂移提示。观察范围不是置信区间，单场不输出正式95%区间、显著性或等效性结论。粗筛成绩不合并到最终复测。零命中可作为有效表现，但不能用极小数替代零分制造巨大优势。精度退步、疼痛或缺少稳定实用优势时，可以保留原设置；边界领先只提示范围外未测，不外推最佳值。

## 数据和迁移

主存储键继续使用 `senslab.personal.v1`，工作区升级到 `storageVersion: 3`。保留原 `.pre-single-v1` 备份，并在升级深度模式前将完整原始串另存为 `senslab.personal.v1.pre-deep-v2`；仅在备份与保存成功后使用新增工作区字段。备份失败时保留原工作区并禁止保存覆盖；读取或校验失败时也保留原始存储串，可通过导出JSON原样取回，再导入有效备份恢复，不应直接清空后重来。

旧 `studies` 记录保留原多日协议与结构。单次实验仍放在 `singleStudies`：10/20分钟继续使用 `senslab-session/1`，120分钟使用 `senslab-session/2` 和 `mode: 120min`；不把旧成绩变为新协议复测。新记录保存 `sessionId`、`sessionSegment`、`phase`、`round`、`conditionId`，以及设置/校准快照、来源与估计状态、冻结规则、顺序与种子、有效时长、评分、输入质量、中断与重试。JSON/CSV可区分协议和阶段；旧记录没有的新字段保持兼容，不补造测量元数据。“导出本次报告”只导出所选实验的可读报告，不夹带其他实验。导入前保存当前工作区到 `.pre-import`，导入仍会替换当前工作区，因此先导出外部备份。

刷新、跨午夜或稍后继续应保留已经完成的小任务；长间隔恢复记录为新的会话片段，不能宣称实际连续完成了两小时。必要时只重启相应配对轮，保留原始中断与重试记录，不能只保存最高成绩。设备变化或不想继续时，可结束本次并保留记录，未完成实验不产生完整推荐。上述迁移、恢复和完整任务流程的实际验收状态见 `QA.md`。

## 源码、构建与恢复

需要 Python 3.10+；应用无后端、账号或外部运行库。真实源码位于 `src/`：`index.html`、`styles.css`，以及按顺序执行的 `onboarding.js`、`core.js`、`session-core.js`、`session-ui.js`、`app.js`。编辑源码后执行：

```sh
python build.py
python tests/package.test.py
```

构建将所有样式和脚本一次性内联为 `SensLab-Personal.html`，再生成 `app.html.gz` 和按编号拼接的8个gzip分片。`index.html` 使用完整HTML摘要作为分片请求的版本参数，减少CDN混合旧新分片。直接分片请求失败时，只向该公开仓库的官方GitHub API请求一次固定Git blob版本的gzip；不发送个人设置、成绩、备份或令牌。备用响应须通过格式、base64、大小和Git blob SHA-1检查。两条路径最终都必须解压并通过**完整最终HTML的SHA-256**才执行。摘要失败不改用其他版本；两源均失败或任何完整性校验失败时停止加载。

构建同步 `index.html` 和 `restore.py` 中的摘要、`transport-manifest.json`、`deployment.json` 及 `SHA256SUMS.txt`。manifest记录版本、完整HTML摘要、gzip的`gzip_git_blob_sha`及`chunks`内8片元数据；deployment同步gzip blob标识，并明确标记`local-only`。在线分片或API gzip的解压结果与离线HTML必须逐字节一致，因此其CSS、脚本内容与执行顺序相同；存储源、权限和真实设备差异仍须单独验证。

需要从分片恢复完整最终网页时：

```sh
python restore.py
python restore.py --output restored-SensLab.html
```

恢复脚本先验证最终 HTML 摘要再写文件；若同名文件已是相同内容，只确认成功，不重写；若内容不同则拒绝覆盖。恢复结果已包含新协议与教程，无须加载旧补丁脚本。

## 自动化检查

从 `senslab/` 执行：

```sh
node --check src/core.js
node --check src/session-core.js
node --check src/session-ui.js
node --check src/app.js
node --test
python build.py
python tests/package.test.py
```

加载器浏览器集成检查需另装 Playwright 与 Chromium：

```sh
python -m pip install -r tests/requirements.txt
python -m playwright install chromium
python tests/loader.test.py
python tests/browser-session.py
```

加载器脚本默认使用Playwright管理的Chromium；DOM脚本在本Windows验收环境优先使用已安装Edge，未找到时使用Playwright的Chromium。两者都创建隔离上下文。已有浏览器均可以设置 `CHROMIUM_EXECUTABLE_PATH`；PowerShell示例：

```powershell
$env:CHROMIUM_EXECUTABLE_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
python tests/loader.test.py
python tests/browser-session.py
```

`package.test.py` 不启动浏览器，校验当前源码、全部脚本、完整HTML、gzip、分片、哈希、元数据及恢复脚本的正常/篡改分支。`loader.test.py` 使用临时localhost服务和隔离浏览器上下文，执行原生fetch、gzip解压和WebCrypto，检查线上入口与完整HTML的脚本一致性、缺片/API失败、有效gzip篡改、官方API回退成功以及坏base64/错误blob/错误最终摘要。官方API响应由隔离测试拦截提供，不代表真实托管或API可用性。它不接触用户浏览器存储，不生成用户成绩，不证明真实鼠标测量精度。

真实输入验收要在原使用环境、原保存设置与有效校准上直接进行：确认无需重做尺子校准即可进入新实验；确认固定准星、输入诊断、Pointer Lock、四任务操作、暂停恢复，以及计划时间与额外等待分别记录。自动化模拟不能声称已实测通过，也不能证明游戏表现改善。

## 发布

构建与测试不会推送仓库或部署网站。实际发布时应将新`index.html`、全部8个分片和`app.html.gz`作为同一版本提交到指定公开仓库，确保备用API可取得构建时固定的gzip blob；同批提供完整HTML、恢复脚本与摘要文件。混合旧新分片会被完整性校验拒绝。不能只替换离线HTML，让线上保留旧实验。上传后仍须在实际托管地址验证加载、API回退、存储、恢复与真实输入，并记录部署证据。GitHub公开API仍受网络与速率限制，本地通过不证明线上可用。未完成这些步骤时，交付说明应保持“本地版本，尚未上线”。

## 方法参考

方法参考为 NVIDIA [Mouse Sensitivity in First-Person Targeting Tasks](https://research.nvidia.com/index.php/publication/2023-07_mouse-sensitivity-first-person-targeting-tasks)、MDN [Pointer Lock API](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_Lock_API) 与 [movementX](https://developer.mozilla.org/en-US/docs/Web/API/MouseEvent/movementX)。原始输入请求、鼠标锁定和物理单位换算需结合设备校准。120分钟以及保留的10/20分钟安排、候选倍率、适应时长、最低数据量和守门线均为本工具的工程设计，不是论文原样验证的标准流程，也不构成个人最优灵敏度的科学保证。
